# Join Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The server turns away, with a readable reason, any joining player whose game does not run a matching Blue's Archery Overhaul.

**Architecture:** One Unity-free file holds the wire layout of the two join messages and the decision rule, fully unit-tested. One game-facing file adds a step to the game's own join sequence on the server, a message handler on each side, and the `[Join]` settings. The server greets (Here), the player's game answers (Hello), the rule decides, and a refusal goes out as the game's own join refusal before the step fails.

**Tech Stack:** C# (net472, Unity 2020.3 Mono), MelonLoader 0.7.3, Harmony, the mod's own bit reader/writer interfaces (`IBitWriter`, `IBitReader`, `StreamBits`), the console test runner `BluesArcheryOverhaul.Tests`.

**Renamed since this plan was first written (2026-11-20):** the mod is Blue's Archery Overhaul (folder, namespace, DLL and cfg `BluesArcheryOverhaul`; the play-test tools are the separate `BluesArcheryTestKit`). The version is the constant `Main.Version`; `tools/stage-build.sh` sets it. A game still on the old `QuickshotRing.dll` (0.18.3 or older) has no gate code and is refused as a game without the mod.

**Spec:** `docs/superpowers/specs/2026-11-20-quest-port-join-gate-design.md`, section "Piece 1: the join gate". Pieces 2 and 3 (Quest) are not in this plan.

## Global Constraints

- Work on a branch `join-gate` cut from `main`. Stage files by explicit path; never `git add -A` (`.claude/` and `BluesInGameStringTool/` are untracked and stay out).
- No change to how any shot, skill or setting behaves. The only new behaviour is at join.
- Network traffic: exactly one Here (server to joining game) and at most one Hello (game to server) per join; nothing during play; nothing at all with `[Join] Check = off`.
- The game writes a message type in 5 bits. Our number is one of 3, 5, 8, 14, 16, 19, 27, 31 and never 18 (SyncLib).
- Unity types stay out of `JoinRules.cs` (it is compiled by the tests).
- A fault inside the gate must never refuse a player: only a decided refusal fails the join step.
- No strings from the joining game are ever logged or sent back; Hello carries numbers only.
- Every new Harmony patch and message handler gets a timing section (`static readonly int T = Timing.Section("...")`, `using var _t = Timing.Begin(T);` first statement). `Timing` is main-thread only: never call it inside the async join step.
- New log lines start `[Archery] Join: `. One Summary line per join; warnings and errors always log.
- Settings in `[Join]` are per machine, not `[shared]`.
- Build must finish with 0 warnings; `dotnet run --project BluesArcheryOverhaul.Tests -c Release` must print `ALL PASS (N)`.
- Version for this build: `0.19.1`. Wire number: `1`.
- Refusal texts, verbatim (X = the server's mod version, Y = the joining game's):
  - no answer: `This server needs the mod Blue's Archery Overhaul (X). Install it, then join again.`
  - older wire: `Your Blue's Archery Overhaul Y is too old for this server's X. Update it, then join again.`
  - newer wire: `Your Blue's Archery Overhaul Y is newer than this server's X. The server needs an update first.`
  - settings differ (only with `SettingsMismatch = refuse`): `Your Blue's Archery Overhaul settings differ from this server's. Ask the server owner for its BluesArcheryOverhaul.cfg, then join again.`

## Review Focus

1. **A slow game answers after the wait.** Expected: the wait is `[Join] AnswerSeconds`, held to 1..60 s, a broken value reads as 5; the log line says no answer came. Pinned in Task 1 (`AnswerSeconds`).
2. **A short, garbage or foreign message on our number** (another mod, a hostile client). Expected: read as malformed, treated as no answer, never an exception out of the handler. Pinned in Task 1 (`ReadHello` malformed cases); the handler's try/catch is Task 2.
3. **A typo in `[Join] Check`** (`refsue`). Expected: treated as `refuse` (the shipped default) with one warning naming the three valid values. Pinned in Task 1 (`ParseCheck`).
4. **Hellos that are never collected** (a game answers, then drops; a flood of Hellos). Expected: the waiting table never grows past 256 and a taken or dropped entry is gone. Pinned in Task 1 (`JoinHellos`).
5. **The gate itself throws** (a null `UserInfo`, a disposed connection). Expected: the player is let in and one error is logged. No unit test can reach it; Task 2 Step 5 states the structure and the reviewer checks it.

```csharp
enum JoinCheck { Refuse, Log, Off }
enum JoinPlatform { Pc = 0, Quest = 1, Unknown = 3 }

struct ModVersion {                       // each part held to 0..1023
    public int Major, Minor, Patch;
    public static ModVersion Parse(string? text);   // "0.19.1" -> 0,18,4; leading digits of each part; anything else -> 0
    public override string ToString();              // "0.19.1"
}

struct JoinHere  { public int Wire; public ModVersion Version; }
struct JoinHello { public int Wire; public ModVersion Version; public uint Check; public JoinPlatform Platform; }

static class JoinWire {
    public const int Version = 1;          // THE wire number: raise on every build friends need
    public const int Message = 27;         // the game MessageType value both messages use
    public static readonly int[] FreeMessages = { 3, 5, 8, 14, 16, 19, 27, 31 };
    public const int RefusedResult = 60;   // a join-result integer the game does not define
    public const uint KindHere = 1, KindHello = 2;
    public const int HereBits = 54, HelloBits = 88;
    public static void WriteHere(IBitWriter w, JoinHere h);
    public static WireRead ReadHere(IBitReader r, out JoinHere h);
    public static void WriteHello(IBitWriter w, JoinHello h);
    public static WireRead ReadHello(IBitReader r, out JoinHello h);
}

struct JoinVerdict { public string? Problem; public bool Refuse; public bool SettingsDiffer; }

static class JoinRule {
    public static JoinCheck ParseCheck(string? text, out bool known);
    public static bool ParseSettingsRefuse(string? text, out bool known);   // "refuse" -> true, "log" -> false
    public static float AnswerSeconds(float setting);
    public static JoinVerdict Decide(JoinHello? hello, int serverWire, ModVersion serverVersion, uint serverCheck,
                                     JoinCheck check, bool settingsRefuse);
    public static string Line(string name, JoinHello? hello, JoinVerdict verdict, JoinCheck check);
    public static string Ascii(string? text, int max);
}

sealed class JoinHellos {                 // the server's Hellos waiting for their join step
    public const int Max = 256;
    public void Put(int connection, JoinHello hello);      // at Max, the table is cleared first
    public bool Take(int connection, out JoinHello hello); // removes it
    public void Drop(int connection);
    public int Count { get; }
}
```

Layouts, most significant bit first, every field through `IBitWriter.Write(value, bits)`:
- Here: kind 8 (`KindHere`), wire 16, major 10, minor 10, patch 10.
- Hello: kind 8 (`KindHello`), wire 16, major 10, minor 10, patch 10, check 32, platform 2.

`ReadHere`/`ReadHello` return `WireRead.Malformed` when `BitsLeft` is less than the layout or the kind is wrong, else `WireRead.Ok`. A platform value of 2 reads as `Unknown`.

  `static async Task Step(Connection connection, Action<string> progress)`:

```csharp
JoinVerdict verdict = default; string reason = "";
try {
    var (check, seconds, settingsRefuse) = <Values>;
    if (check == JoinCheck.Off) return;                       // nothing sent
    connection.Send(null, (MessageType)JoinWire.Message, <writes Here: JoinWire.Version, this mod's version>);
    JoinHello hello = default; bool answered = false; int waited = 0, limit = (int)(seconds * 1000f);
    while (!connection.IsDisposed && waited < limit) {
        lock (hellos) answered = hellos.Take(connection.Identifier, out hello);
        if (answered) break;
        await Task.Delay(100); waited += 100;
    }
    if (connection.IsDisposed) { lock (hellos) hellos.Drop(connection.Identifier); return; }   // they left: no line, no refusal
    verdict = JoinRule.Decide(answered ? hello : (JoinHello?)null, JoinWire.Version, <this mod's version>, Cfg.SharedChecksum, check, settingsRefuse);
    string name = JoinRule.Ascii(connection.UserInfo?.Username ?? connection.PlayerName, 40);
    string line = JoinRule.Line(name, answered ? hello : (JoinHello?)null, verdict, check);
    if (verdict.Problem != null) MelonLogger.Warning(line); else if (Logs.Summary) MelonLogger.Msg(line);
    reason = verdict.Problem ?? "";
} catch (Exception e) {
    MelonLogger.Error($"[Archery] Join: the check itself failed, so the player is let in: {e}");
    return;                                                   // a fault never refuses
}
if (!verdict.Refuse) return;
// decided refusal: ours must reach the joining game before the game's own "Failed join prerequisites."
try {
    string text = JoinRule.Ascii(reason, 160);
    connection.Send(null, MessageType.RequestJoinResponse, (c, s) => {
        bool no = false, no2 = false; int result = JoinWire.RefusedResult;
        s.SerializeBool(ref no); s.SerializeBool(ref no2); s.SerializeInteger(ref result); s.SerializeString(ref text);
    });
    connection.FlushPacketManagers();
    await Task.Delay(500);
} catch (Exception e) { MelonLogger.Error($"[Archery] Join: could not send the refusal text: {e.Message}"); }
throw new InvalidOperationException("Blue's Archery Overhaul refused the join: " + reason);
```

  This body is given in full because the order (ours first, then the throw) and the fault rule (only the last line may fail a join) are the design. No `Timing` call and no Unity object is touched in it: its continuations after `await` are not promised to be on the main thread.
